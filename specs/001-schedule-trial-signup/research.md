# Research: Расписание групп и запись на пробный урок

## R1. Отображение недельного расписания

**Decision**: `react-big-calendar` в режиме `week` (без `month`/`day`). Группы хранят шаблон повторяемости (день недели + время), а компонент генерирует конкретные события-вхождения в окне «текущая неделя + 2 недели вперёд».

**Rationale**: Библиотека зафиксирована стеком конституции; генерация событий из шаблона — стандартный способ показать повторяющееся расписание в RBC (она не имеет встроенной рекуррентности).

**Alternatives**: `month`-вид — слишком густой для чтения; `agenda` — теряется визуальная сетка недели; своя HTML-таблица — отклонено пользователем при выборе стека.

## R2. Локализация календаря

**Decision**: `dateFnsLocalizer` из react-big-calendar + `ru` локаль date-fns; свои `formats`/`messages` на русском («неделя», «сегодня», сокращённые дни/месяцы).

**Rationale**: date-fns уже нужна для генерации дат и форматирования; отдельная зависимость (dayjs/luxon) не требуется.

## R3. Модель занятости и лимит 8 человек

**Decision**: Базовое число студентов группы — статичное поле `enrolled` в `src/data/groups.json`. Записи на пробный урок — zustand-стор с `persist` в localStorage. Свободных мест на занятие: `8 − enrolled − activeTrials(groupId, date)`.

**Rationale**: Бэкенда нет (конституция); разделение «штатная занятость из данных» + «пробные из стора» даёт правдоподобную картину и тестирует edge case «мест нет».

## R4. Выбор даты пробного урока

**Decision**: Функция `nextOccurrences(group, days=14)` — генерирует даты всех занятий группы на 14 дней вперёд от сегодня; недоступные (мест нет) помечаются и не выбираются. В форме — выбор даты из списка.

**Rationale**: Прямо следует уточнённому FR-005; окно 2 недели ограничивает размер списка и держит сценарий «ближайшего урока».

## R5. Форма записи и валидация

**Decision**: Нативные управляемые поля + утилита `validateBooking`: имя ≥ 2 символов; телефон нормализуется (вырезаем не-цифры, `8…` → `+7…`, итог 11–15 цифр); email опционален, проверка простым regex; ошибки — словарь `{field: message}` на русском.

**Rationale**: Одна маленькая форма — библиотека форм (react-hook-form) не в `requirements.txt` и не оправдана; правила просты для ручной реализации.

## R6. Одна активная запись на телефон

**Decision**: Ключ записи — нормализованный телефон. При отправке, если запись с тем же телефоном активна, показывается экран/блок «у вас уже есть запись» с кнопкой «Перезаписаться» (старая отменяется, создаётся новая).

**Rationale**: FR-007; телефон — самый стабильный «ключ личности» без регистрации.

## R7. Структура модуля и маршрут

**Decision**: Модуль `src/modules/schedule/` (`SchedulePage.jsx`, `components/`, `lib/`), данные `src/data/groups.json`, стор `src/store/bookings.js`. Маршрут `/schedule`; `/` временно редиректит на `/schedule`.

**Rationale**: Конституция «Module Isolation» — всё своё в папке модуля; общие данные/стор — в общих папках, т.к. следующие модули могут их переиспользовать.

## R8. Скаффолдинг приложения

**Decision**: Эта первая фича одновременно поднимает скелет: Vite + `@vitejs/plugin-react`, Tailwind v4 через `@tailwindcss/vite` (`index.css` с `@import "tailwindcss"`), `react-router-dom` с `BrowserRouter`.

**Rationale**: Без скелета модуль некуда встроить; набор файлов минимален и покрывает будущие модули.

## R9. Стилизация react-big-calendar под Tailwind

**Decision**: Импорт базового CSS пакета + переопределение токенов (фон, бордеры, акцент) в `index.css`/CSS-переменными, поверх — Tailwind-классы в кастомном компоненте события.

**Rationale**: RBC требует свой CSS для сетки; смешивать его с Tailwind-утилитами внутри события — рабочая практика.

## R10. Навигация календаря за пределы окна событий

**Decision**: Навигация по неделям в `ScheduleCalendar` ограничена окном генерации событий через `min`/`max` (границы окна «текущая неделя + 2 недели»). Недели за его пределами недоступны.

**Rationale**: Расписание — повторяющаяся недельная сетка, поэтому недели вне окна были бы пустыми и выглядели бы как баг; `min`/`max` — встроенная возможность RBC, дешевле регенерации событий по `onNavigate`.

## R11. Тестирование

**Decision**: Ручная проверка по сценариям `quickstart.md`. Юнит-тесты (vitest + Testing Library) — опционально, после стабилизации UI.

**Rationale**: Зависимости для тестов не в `requirements.txt`; сценарии фичи проверяемы вручную за минуты.
