# Feature Specification: Тест на определение уровня (placement test)

**Feature Branch**: `002-placement-test`

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "Перед записью человек проходит короткий тест (15 вопросов с вариантами ответа) и получает уровень: Beginner, Elementary, Intermediate или Upper-Intermediate. В конце — рекомендация, в какую группу идти."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Прохождение теста и получение уровня (Priority: P1)

Посетитель открывает страницу теста, последовательно отвечает на 15 вопросов с вариантами ответа (по одному правильному в каждом) и по завершении видит свой определённый уровень английского: Beginner, Elementary, Intermediate или Upper-Intermediate — вместе с количеством правильных ответов.

**Why this priority**: Ядро фичи — без теста и результата рекомендация группы невозможна; само по себе это уже ценность для посетителя.

**Independent Test**: Открыть страницу теста → ответить на все 15 вопросов → отображается один из четырёх уровней и счёт «X из 15».

**Acceptance Scenarios**:

1. **Given** посетитель открыл страницу теста, **When** страница загружена, **Then** показан первый вопрос с вариантами ответа и индикатором прогресса («Вопрос 1 из 15»).
2. **Given** посетитель на вопросе, **When** он выбирает вариант ответа, **Then** он может перейти к следующему вопросу; без выбранного ответа переход недоступен.
3. **Given** посетитель ответил на все 15 вопросов, **When** он нажимает «Завершить/Узнать результат», **Then** отображается его уровень (один из четырёх) и счёт правильных ответов.
4. **Given** посетитель на последнем вопросе, **When** он хочет вернуться, **Then** навигация «Назад» возвращает к предыдущим вопросам с сохранёнными ответами в рамках сессии теста.

---

### User Story 2 - Рекомендация группы по результату (Priority: P1)

После получения уровня посетитель видит рекомендованную ему группу школы (соответствующую его уровню) с её данными — уровнем, преподавателем и расписанием — и кнопкой перехода к записи на пробный урок.

**Why this priority**: Это конверсионная цель теста — ответ «в какую группу идти» и следующий шаг к записи.

**Independent Test**: Пройти тест → на экране результата видна конкретная рекомендованная группа (совпадающая с определённым уровнем) и кнопка «Записаться на пробный» ведёт на страницу расписания.

**Acceptance Scenarios**:

1. **Given** посетитель получил уровень Elementary, **When** открыт экран результата, **Then** показана рекомендованная группа уровня A2 с преподавателем и расписанием.
2. **Given** показан экран результата с рекомендацией, **When** посетитель нажимает «Записаться на пробный», **Then** он переходит на страницу расписания (маршрут `/`); подсветка/предвыбор рекомендованной группы выполняется, если страница расписания обработает параметр `group`.
3. **Given** у рекомендованной группы нет свободных мест на ближайшие занятия, **When** показан экран результата, **Then** группа всё равно показана как рекомендация, но помечена «мест нет», и предложены ближайшие по уровню альтернативные группы со свободными местами.

---

### User Story 3 - Повторное прохождение и сохранение результата (Priority: P3)

Посетитель, уже проходивший тест, при повторном открытии видит свой сохранённый результат (уровень, счёт, дату) и может перепройти тест — результат обновляется.

**Why this priority**: Удобство повторного визита; базовая ценность уже доставлена в US1+US2.

**Independent Test**: Пройти тест → перезагрузить/переоткрыть страницу → результат на месте; нажать «Пройти заново» → тест начинается с нуля и по завершении обновляет результат.

**Acceptance Scenarios**:

1. **Given** посетитель ранее прошёл тест, **When** он открывает страницу теста, **Then** показан сохранённый результат с кнопкой «Пройти заново».
2. **Given** посетитель перепроходит тест, **When** он завершает его, **Then** сохранённый результат заменяется новым.

---

### Edge Cases

- Посетитель закрывает страницу посередине теста — прогресс незавершённого теста не сохраняется; при возврате тест начинается заново.
- Попытка отправить тест без ответов на все вопросы — блокируется (кнопка результата активна только после ответа на все 15).
- На некоторых устройствах вопросы и варианты должны оставаться читаемыми на экране ≥ 360px.
- Два одинаковых прохождения подряд — результат просто обновляется, дубликатов не создаётся.
- Тест пройден, но рекомендованная группа не имеет свободных мест — показываются альтернативы.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST предоставлять тест из ровно 15 вопросов; у каждого вопроса 4 варианта ответа, ровно один правильный.
- **FR-002**: Система MUST показывать прогресс («Вопрос N из 15») и пошаговую навигацию «Назад»/«Далее»; переход к следующему вопросу доступен только при выбранном ответе.
- **FR-003**: Система MUST определять уровень по количеству правильных ответов по порогам: 0–4 → Beginner, 5–8 → Elementary, 9–12 → Intermediate, 13–15 → Upper-Intermediate.
- **FR-004**: Система MUST показывать экран результата: уровень, счёт «X из 15» и краткое текстовое описание уровня.
- **FR-005**: Система MUST рекомендовать конкретную группу по таблице соответствия: Beginner → `group-1` (A1), Elementary → `group-2` (A2), Intermediate → `group-3` (B1), Upper-Intermediate → `group-4` (B2). Уровни выше Upper-Intermediate (C1 — `group-5`, IELTS Prep — `group-6`) тестом не определяются.
- **FR-006**: На экране результата MUST быть переход к записи на пробный урок — на страницу расписания фичи 001 (маршрут `/`); предвыбор/подсветка рекомендованной группы выполняется, если страница расписания обработает параметр `group`.
- **FR-007**: Результат теста MUST сохраняться в локальном хранилище браузера (уровень, счёт, дата прохождения) и отображаться при повторном открытии; кнопка «Пройти заново» заменяет результат новым.
- **FR-008**: Тест MUST быть опциональным: запись на пробный урок доступна без его прохождения; тест предлагается как рекомендуемый шаг (баннер/кнопка на странице расписания), но не блокирует запись.
- **FR-009**: Точка входа в тест MUST быть доступна со страницы расписания — баннер/кнопка «Пройти тест на уровень» на странице `/`; дополнительно доступна прямая навигация на `/test`.

### Key Entities *(include if feature involves data)*

- **Вопрос**: id, текст, список вариантов (4), индекс правильного, уровень сложности (для выборки/порядка).
- **Результат теста**: счёт (0–15), уровень (Beginner|Elementary|Intermediate|Upper-Intermediate), дата прохождения.
- **Соответствие уровень → группа**: маппинг четырёх уровней теста на группы `group-1`…`group-4` из фичи 001.
- **Группа** (из фичи 001): переиспользуется для рекомендации (уровень, преподаватель, расписание; занятость — по пробным записям `trial_signups`).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Посетитель проходит тест за ≤ 5 минут (медиана).
- **SC-002**: 100% завершённых тестов показывают корректный уровень согласно порогам и валидный счёт.
- **SC-003**: 100% экранов результата содержат рекомендацию группы с работающим переходом к записи.
- **SC-004**: Сохранённый результат корректно отображается при повторном визите в 100% случаев.
- **SC-005**: Тест остаётся проходимым и читаемым на экранах от 360px.

## Assumptions

- Банк вопросов — вымышленный и правдоподобный: грамматика, лексика, короткое чтение; сложность нарастает от первых вопросов к последним.
- Скоринг — простое число правильных ответов без весов; пороги зафиксированы в FR-003 и настраиваемы в данных.
- Тест — отдельная страница/маршрут `/test`; интеграция с фичей 001 через ссылку на страницу расписания (`/`) и общие данные `src/data/groups.json` + `trial_signups` (localStorage).
- Прогресс незавершённого теста не сохраняется (тест короткий); сохраняется только финальный результат.
- Уровни теста намеренно не покрывают C1/IELTS — эти группы рекрутируются вне теста (например, через школу напрямую).
